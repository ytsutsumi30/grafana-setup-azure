# Web Design Reviewer(実装後ビジュアルレビュー)

対応: 静的サイト / React・Vue等SPA / Next.js等フルスタック / CMS ほかWebアプリ全般。

## DO(やること)

1. 情報収集: 対象URL確認(localhost / ステージング / 本番)→ プロジェクト構造とスタイリング方式(CSS/SCSS/Tailwind/CSS-in-JS等)の特定。
2. 視覚検査: 主要ページを巡回し、`references/visual-checklist.md` の観点(レイアウト / レスポンシブ / アクセシビリティ / 視覚的一貫性)で検査。ビューポートは最低 390px / 768px / 1280px。
3. 修正: 問題を重大度順に整理 → ソースファイルを特定 → `references/framework-fixes.md` のFW別ガイドに沿って最小修正。
4. 再検証: 修正後スクリーンショットで確認し、隣接画面のリグレッションも確認。必要なら2〜4を反復。

## DON'T(やらないこと)

- スクリーンショット等の実表示なしの「見た目」判断。
- 修正と同時のデザイン刷新・リファクタ混入(最小差分で直す)。
- 本番環境への書き込み(本番は読み取り専用レビュー)。

## OUTPUT FORMAT(出力の型)

レビュー報告書:
- 検査対象(URL・ページ・ビューポート)
- 指摘一覧(重大度 High/Mid/Low、症状、スクリーンショット、該当ソース位置)
- 適用した修正(ファイル+差分要約)と再検証結果
