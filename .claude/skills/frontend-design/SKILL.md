# Frontend Design(新規UIのデザイン方向付け)

## DO(やること)

- 題材を固定する: 対象・読者・そのページの唯一の役割を1文で宣言してから設計する。
- 2パスで進める。まず設計プラン: Palette(4〜6色をhexで命名)/ Type(役割別に2書体以上: 個性あるdisplay+読みやすいbody)/ Layout(1文+ASCIIワイヤ)/ Signature(この画面が記憶される唯一の要素)。
- プランを自己批評してから実装: 「同種の依頼でも同じ案になるか?」を確認し、汎用解なら修正点を明示して直す。実装はプランに厳密に従い、全色・全書体をプランから導出。
- 品質フロア(宣言不要・必ず満たす): モバイル対応 / キーボードフォーカス可視 / prefers-reduced-motion 尊重。
- 大胆さは1箇所(Signature)に集中し、周囲は静かに保つ。

## DON'T(やらないこと)

- AI定番3種に逃げない: (1)クリーム背景+高コントラストserif+テラコッタ (2)漆黒+アシッドグリーン単色アクセント (3)hairline罫線の新聞風高密度。ブリーフが明示的に求める場合のみ可。
- 散発的アニメーション、意味を持たない番号装飾(01/02/03)、内容と無関係な飾り。
- セレクタ詳細度の相殺(.section系とelement系の打ち消し合い、特にセクション間margin/padding)。
- 実データがないときの宣伝調ダミーコピー。UI文言は能動態・具体・一貫(「Publish」→トースト「Published」)。エラーは謝らず原因と対処を示す。

## OUTPUT FORMAT(出力の型)

1. 設計プラン(Palette / Type / Layout / Signature の4項目)
2. 自己批評での変更点(1〜3行)
3. 実装コード
