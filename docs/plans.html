入庫・在庫・棚卸し計画

製造現場で利用できる POC 向け在庫管理。在庫は 品目 → ロット → QR 管理単位 の3層で追跡し、現在庫(inventory_balances)と変動履歴(inventory_transactions、追記型)を分離する。

入庫予定→ロット作成→QRラベル発行→QR入庫検品→在庫反映→在庫照会→QR棚卸→差異確認→承認・調整→Grafana監視

在庫ステータス遷移

QR / ロット設計

QR には短い ID のみ(例: QR-LOT-20260705-001-0001)。詳細は DB 側で管理し、長い JSON の埋め込みは避ける。

QRステータス意味
created / received / inspection発行済み / 入庫済み / 検査中
available / allocated / moved利用可能 / 引当済み / 移動済み
consumed / shipped製造使用済み / 出荷済み
on_hold / defective / lost / adjusted保留 / 不良 / 紛失 / 調整済み

ロット品質: pending_inspection approved rejected on_hold expired

受発注・製造指図計画

業務の起点(受注・発注)と製造工程の実績収集を追加し、既存の出荷検品・在庫計画と接続して 2 本の業務フローを閉じる。

ドキュメント連鎖

OCR は既存資産を横展開: FAX/PDF 注文書 → OCR → 確認・修正画面(マスタ照合)→ 受注化。納品書も OCR → 発注明細と自動突合 → 差異表示。読み取り結果をそのまま登録しないことを原則とする(ocr_documents に原本+解析結果を保存)。

OSS Grafana 埋め込み計画

現場端末のアプリ画面内に、ログイン不要でリアルタイム更新される Grafana グラフを iframe 表示する。Grafana Cloud は iframe 埋め込み不可(allow_embedding 変更不可・匿名アクセス不可)のため、OSS 版セルフホストを採用。Cloud は管理者向け運用監視・アラートに役割分担する。

機能Grafana CloudOSS セルフホスト
共有 URL (Public/Shared Dashboards)可可
iframe 埋め込み (allow_embedding)不可可
匿名アクセス不可可
パネル単体埋め込み (d-solo)不可可

構成(ACA 主案 / Cloud Run 併記)

Browser→web (nginx, 外部公開)→/grafana/* → grafana (internal)→Supabase (設定DB + データソース)
観点Azure Container AppsCloud Run
既存アプリとの同居済み (web/api 稼働中)新規展開が必要
内部サービス間通信internal ingress で完結ingress 制限 + 認証/VPC 設定
スケールmin replicas 1 推奨min-instances 1 推奨 (コールドスタート回避)
位置づけ主案 既存 Terraform に追加代替 GCP 展開時

必須設定

GF_SECURITY_ALLOW_EMBEDDING=true
GF_AUTH_ANONYMOUS_ENABLED=true
GF_AUTH_ANONYMOUS_ORG_ROLE=Viewer
GF_SERVER_ROOT_URL=https://<app>/grafana/
GF_SERVER_SERVE_FROM_SUB_PATH=true
# 設定DBを Supabase に外出し (ステートレス化)
GF_DATABASE_TYPE=postgres
GF_DATABASE_HOST=<pooler>:5432
GF_DATABASE_SSL_MODE=require

設定 DB を外出ししないと再起動でダッシュボードが消える。データソースは読み取り専用ロールでアプリ DB を参照。

埋め込み方法

<!-- パネル単体 -->
<iframe src="/grafana/d-solo/<uid>/<slug>
  ?orgId=1&panelId=2&from=now-6h&to=now
  &refresh=30s&theme=light"></iframe>

<!-- ダッシュボード全体 (キオスク) -->
<iframe src="/grafana/d/<uid>/<slug>
  ?kiosk&refresh=30s"></iframe>

var-xxx テンプレート変数で、アプリ側の選択中拠点・品目を引き渡して絞り込み表示できる。

セキュリティ・フェーズ・完成条件

セキュリティ設計

匿名は Viewer 固定(編集・Explore 不可)。埋め込み用 Org/フォルダを分離。Grafana は internal ingress で直接公開しない(閲覧は必ず nginx 経由 → アプリの M365 認証・IP 制限がそのまま効く)。DB ユーザーは SELECT のみ。admin/admin を本番に持ち込まない。/grafana/ にレート制限。

実装フェーズ

  • Phase 1 ローカル検証docker-compose に grafana 追加・nginx プロキシ・iframe 仮組み
  • Phase 2 ダッシュボード整備shipping-floor / inventory を JSON + 投入スクリプトで管理
  • Phase 3 Supabase 対応設定 DB 外出し・読み取り専用ユーザー・ステートレス確認
  • Phase 4 ACA 展開Terraform 追加 (internal ingress)・secrets・本番確認
  • Phase 5 Cloud Run 展開(GCP 採用時のみ)ingress 制限・サービス間認証・min-instances=1
  • Phase 6 運用整備ダッシュボード CI 投入・稼働監視・キオスク常時表示ルール

デザイン・UI・機能改善計画

現場端末での操作性と信頼性を高め、今後の機能拡張(在庫・受発注・Grafana 埋め込み)を低コストで載せられる UI 基盤を整える。

現状の課題

HTML 47 本中、本番は 15 前後(safari*、qr-inspection 系 7 種などが混在)。全ページがインライン style 個別実装。外部 CDN 依存。PWA 未完成(SW なし)。「戻る」連鎖のナビ。

基本方針

先にページ整理+共通レイアウト → 全画面へ一括適用できる状態を作る。現場モード / 管理モードの分離。CSS 変数トークンで統一。CDN ローカル化。PWA でオフライン耐性。

モード分離

現場: 大ボタンランチャー(検品/ピッキング/棚卸)、1 画面 1 タスク、PWA 起点。管理: サイドバー付き(指示・実績・マスタ・QC・モニタリング)。

ページ整理

区分内容
残す (約15)index / qr-inspection3(rename) / pps / ItemPicking / maintenance / 各マスタ / shipping-instructions / inventory / monitoring / qc-* / ocr / logs / system-config
_archive へsafari*(6) / qr-inspection 旧版(7) / index-org,original / mockup 系 / camera-test / QRPOC / android / aws-system-diagram / exhibition-flyer / *.backup-*

nginx で _archive/ を遮断し、Docker イメージから除外。
