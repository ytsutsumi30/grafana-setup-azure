# NotebookLM レビュー用ブリーフィング

## 目的

この資料は、NotebookLM に `notebooklm-combined-source.pdf` と `notebooklm-prompts.md` を投入した後、最初のレビュー会議で使うための進行メモです。

## レビュー対象

- 出荷検品アプリ本体
- QR コード管理
- ロット管理
- 在庫・入庫・受注・出荷指示
- 棚卸
- OCR 取込
- 製造指図・工程実績
- トレーサビリティ
- Grafana Cloud 最小監視
- Azure Container Apps / Supabase / M365 認証

## 最初に NotebookLM で生成するもの

1. 概要
   - POC の目的、対象業務、現在の実装済み範囲。
2. FAQ
   - 現場担当者、管理者、IT 担当者から出そうな質問。
3. ブリーフィング資料
   - 10 分説明用の要点。
4. 実装ロードマップ
   - 完了済み、未完了、次アクション、リスク。

## 会議で確認する観点

### 業務

- 出荷指示が複数品目・複数ロットに対応しているか。
- 確定済みロット引当を照合の正として扱えているか。
- QR スキャンごとに数量入力する POC 方針で現場運用に耐えるか。
- NG 理由分類、コメント、監査ログが十分か。
- 出荷完了後の数量・ロット修正を理由入力必須で扱えるか。

### 在庫・入庫

- 入庫時にロットと QR 単位を作成できるか。
- 在庫残高と在庫移動が追跡できるか。
- 保留、不良、引当済などの在庫状態が業務に合っているか。
- 棚卸差異を監査ログ付きで反映できるか。

### 受注・出荷

- 受注から出荷指示を生成できるか。
- 出荷指示からロット引当、PPS、QR 検品へ自然につながるか。
- 帳票と履歴が出荷完了後の監査に耐えるか。

### 製造・トレーサビリティ

- 材料投入と完成品入庫がロット単位でつながるか。
- QR、ロット、伝票、製造指図で横断検索できるか。
- 将来 QR 個体 ID とロット番号を分離する設計余地があるか。

### 技術

- Azure Container Apps と Supabase の POC 構成が妥当か。
- M365 ログインと Bearer token 運用への移行方針が明確か。
- Grafana Cloud 最小監視の KPI が業務判断に使えるか。
- API、画面、DB、監査ログ、テストの抜け漏れがないか。
