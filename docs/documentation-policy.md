# ドキュメント作成方針

作成日: 2026-07-08

## 基本方針

このプロジェクトの基本ドキュメントは日本語で作成する。

対象:

- 計画書
- 設計書
- 運用手順
- 現場レビュー資料
- Runbook
- 移行手順
- 業務フロー説明
- 技術的負債、改善計画

英語を使うのは、以下に限定する。

- コマンド
- API パス
- テーブル名
- カラム名
- 環境変数
- エラーコード
- GitHub Actions などのツール固有名
- 外部サービスの正式名称

## HTML First 方針

システム構成、業務フロー、画面遷移、データ連携、ロードマップなど、図表が必要な資料は HTML First で作成する。

HTML First の対象:

- システム構成図
- Azure / Supabase / M365 / Grafana の構成図
- 業務フロー図
- 画面遷移図
- データモデル図
- ロードマップやフェーズ表
- 現場レビュー用の説明資料
- 経営、現場、非エンジニア向け説明資料

理由:

- ブラウザでそのまま確認できる。
- 表、図、色分け、タブ、チェックリストを表現しやすい。
- PowerPoint 化や PDF 保存に展開しやすい。
- 現場レビュー時に見せやすい。

## Markdown を使う資料

Markdown は、実装者向けの詳細資料に使う。

対象:

- API 設計詳細
- DB スキーマ詳細
- 実装タスク一覧
- コマンド手順
- CI / テスト手順
- Runbook の詳細版
- 差分メモ

ただし、Markdown でも図表が中心になる場合は、別途 HTML 版を作る。

## ファイル配置ルール

```text
docs/*.md      実装者向け詳細文書
docs/*.html    図表、説明、ポータル、レビュー向け文書
```

代表例:

| 用途 | 推奨形式 |
|------|----------|
| 詳細設計 | Markdown |
| システム構成図 | HTML |
| 業務フロー | HTML |
| API 一覧 | Markdown |
| DB スキーマ | Markdown |
| ロードマップ | HTML + Markdown |
| 現場レビュー手順 | Markdown |
| 現場レビュー説明資料 | HTML |
